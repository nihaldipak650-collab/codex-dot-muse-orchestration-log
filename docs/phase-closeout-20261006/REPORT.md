## 二、弯路：也包括需求整理和本线程判断

**把可复用过早等同于独立runtime。** 早期复盘已建议薄Skill/适配，后来又围绕HTTP/SSE封装，增加两条路径和恢复接缝。保留现成工具、只脚本化确定性收件更值得先比较。自写通道增加复杂度，但不是超时根因已证；注册路径也曾无返回。[R12、V3 evidence]

**验收越写越窄。** ACK、状态词、单worker、安全边界逐项变严，完整的“收包→本地读→继续”却掉了。3h行为回归通过没有义务证明新的文件工作流；错误是把它表述成整体能力升级。应给短的用户旅程和少量反例，而不是不断增加限制段落。

**连接被反复猜。** 端口监听、插件页、标签可见、某次调用返回、授权完成不是同一个事实。此前“必须自己开tab”“必须出现Welcome”“timeout就是扩展断线”都超出证据。需要人工时给一个具体动作；官方client/tab-group/profile只作排查依据。[E03、E05]

**规范测试增加，真实接缝没有自动减少。** V3修复跨transport、延迟collect、原始字节等是有用工作，但不能替代实际provider选择器、下载字节可达和安装发现。旧包是candidates.csv/多种manifest/Muse嵌套结构，新合同是results文件和哈希映射；没有证明历史包直接兼容。[Z01–Z04、V3 source]

**“能力超集”不该变成必须重造所有旧功能。** 应保护的是用户旅程；允许现成工具、明确转换、按现场能力降级。Muse历史也成功交付过ZIP，不应永久规定Muse只走正文。合法零结果、部分可读结果和坏文件也要分开。

**上传了代码，但入口滞后。** README示例默认standalone，却说registered首选；旧状态页仍是14:02，缺下午结果入口。下一位Agent于是继续从缩水或过时认知起步。修法是补当前入口和来源层，不静默改历史。

**任务“跑满时长”与“交付完成”混用。** 空闲时间有机会利用，但额度用完/一直忙不是收益。真实交付提前完成应停，耐久试验另用固定负载；不能为保持忙碌无限生成gap。没有足够工时记录，不能给返工比例。

## 三、可复用经验

核心原则：**保存一条用户真正跑通的路径，让新封装用同样的真实输入和交付证明自己。**

1. 当前入口与历史证据分开；69/71/74、不同计时各自带范围。
2. 验收用户旅程：发任务、拿交付、本地打开、定向返工、同线程继续。
3. 先有最小收件依据，下一题独立时再续发；深处理放在worker忙时。
4. 不确定不是失败，也不是成功；观察、补收、补交与重做任务分开。
5. 自动检查字节、格式、身份；人判断目标、价值、权限与结论。
6. 路径不等于字节；说明浏览器/MCP宿主与协调器文件可达性。
7. 没有真实失败或用户收益依据，不增加新框架；总控唤醒另设验证。

B06未发送、旧回复、迟显、补收不重发、重复ZIP、坏包与跨线程值得测试；旧包兼容、空结果、续发后旧附件仍需明确验收。本次不新增这些测试。

最短复用流程：当前入口→一条真实交付→已有可用通道→保存回执/本地结果→一个失败只修一个接缝→同题复验→更新入口并停止。

## 四、具体缺口驱动的外部研究

本轮没有安装或运行外部项目。此前五个浅clone的独立参考目录及commit已核实；不是五个依赖都已接入。

| 参照 | 相似点与借鉴 | 不搬什么 / 证据边界 |
|---|---|---|
| Browse Code、chatgpt-browser-agent | 网页聊天→外部真实执行/反馈→下一轮；会话接续 | 不搬自动shell权限、免费/隐私宣传和绕限假设；README/源码参考，不是实测 |
| agent-mcp | 浏览器AI provider受上层MCP管理，整体形状接近 | 作者披露最长回答“共识”、固定分数、人工review不能resume；不是成熟底座 |
| 原生Skills、codex-browser-bridge | 简短Skill入口配工具/可选脚本 | 官方instruction-only是默认；不必为叫Skill重造runtime |
| Playwright扩展/MCP/Download、Playwriter | client/tab绑定、请求歧义、真实下载、批量动作 | 不能把远端路径当本地文件，不能由README承诺更快；未换控制栈 |
| Sessions、A2A | session/thread连续性；任务/消息/产物分开 | 规范和SDK不等于网页worker原生提供同样接口 |
| LMAS、resume-after-wait | 长等待移出模型轮询，准确唤醒owner | 本地PID结束不是网页reply事件；Unix/tmux/宿主条件不能直接套Windows |
| Anthropic长任务harness、MAST | 增量交接、上下文接手、失败分类 | 论文/作者案例不是本项目提速数据；未复现 |

外部证据见E01–E22。Hacker News取得作者/用户自述，不当独立效率评估。Bilibili取得Record & Replay入口，没完整取得视频/字幕；X、YouTube定向搜索没有获得可支撑升级结论的一手完整内容；Discord未取得可靠相关公开讨论。

收敛为四个候选方向：**薄Skill正确接入；真实旧包与文件可达；会话持续和总控唤醒分开；用用户主动操作时间验证收益。** 不把候选机制地图变成安装清单。DOT/Muse原本就有自己的任务能力，外层只是协调，不应宣称给它们延长了内部推理预算或破解了一小时硬限制。

## 五、价值与继续条件

作为作品，有真实问题、产物和错误演化，值得保留。作为个人能力资产，能体现任务拆解、实验反馈、目标纠偏和AI协作；不证明拥有者独立写完全部代码或掌握全部协议。作为工作流，小批派工、条件续发、单包/inline、本地读取和可追溯回执可迁移，但第二账号/第二任务还需试。

作为产品，完整安装、真实低介入运行、维护成本尚未验证；没有本项目的外部留存/付费证据。作为商业方向，暂缓托管或收费；先确定许可证和平台允许用途。公开可查看/fork不自动等于开放源代码复用许可；无需API key不自动代表允许自动提取或转售。[E16–E17]

最合适的对外表述是“真实失败驱动的网页AI协作研究原型”，展示一次旧实跑、文件证据、修补和当前边界。不使用稳定提效、成熟产品、通用平台等尚无证据的措辞。

**有条件继续：** 只为确认一条真实用户旅程是否比旧手法省主动操作，再做一个有界验证周期。如果持续需要作者救援或外部使用者没有需求，冻结产品化，保留案例与测试。现在停止扩张，不等于否定已有价值。
