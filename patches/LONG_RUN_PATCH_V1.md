# LONG_RUN_PATCH_V1

适用：已有 worker 的长期搜索/研究任务。优先 FORWARD PROGRESS；沿用现成工具，不新建 MCP、SSE、浏览器框架或定时任务。

1. **先定边界。** 记录目标、当前有效截止时间和一份独立工作清单。旧 hard stop 不可偷偷延长。用户明确要求到期后继续时，保留旧窗口统计，另记续跑窗口；未给时长时明示采用一次 60 分钟续跑上限。到新截止时间停止。批次限额仍遵守，但 worker 到限额不代表本地工作结束。
2. **填入不等于发送。** 提交后检查 RUN_ID 是否在输入框之外的用户消息中，以及 composer 是否清空；必要时刷新一次。禁止用整个页面包含 RUN_ID 或 prompt 内的 COMPLETE 字样证明发送/完成。已读只证明送达，不证明正在工作。结果必须是独立的 worker 回复。
3. **优先恢复推进。** 距最后可见进展 20–30 分钟，主动看消息和输入框、必要时刷新。仍是草稿就提交；发送不确定的搜索任务可以再试一次，保留原 RUN_ID 并标 attempt=2，后来按实体/URL 去重。确认送达但迟迟不答，可发一次简短进度/缩小范围请求。不要为避免一次偶发重复而无限等待。
4. **等待期间做别的。** worker 慢时，立即做授权范围内独立工作：解析旧 raw 输出、去重、修补证据边界、完善已有报告/缺口清单。约 5–10 分钟再查；不用 30 秒轮询填满工作时间。同一无效动作重复 2–3 次就换下一件事；没有独立工作时用有界等待，不制造无意义修改。
5. **每约一小时轻量 QC。** 写三句话：新增了什么？是否主要在等/查状态？下一件最有价值的事是什么？若只在轮询或写状态，立刻换工作；checkpoint 写完继续执行。
6. **结束前检查。** 只有目标达成、有效 hard stop、用户叫停，或真实 blocker 且无可做的独立工作才结束。慢 worker、写完报告、单 lane 用完批次都不是单独的结束理由。报告明确区分已送达、无进展、结果已回收；记录未完成项和重入动作，不声称后台仍运行。

允许有限重试仅适用于公开检索；报名、付款、发布、删除等副作用不适用。保留去重、权限边界和 hard stop。
